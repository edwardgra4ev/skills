# inspect-baw-processes

Найти и исследовать экземпляры процессов IBM BAW; выполнить явно порученное действие над экземпляром.

**Тестовый, непроверенный навык.** Полная проверка на IBM BPM/BAW не выполнена. В анализаторах обнаружены пропуски типов данных и ошибки классификации; сверяй результаты с исходными артефактами. Не представляй результат как подтверждённый без проверки.

## Работа в Codex

- Используй контекст пользователя и локальные правила проекта. Достаточный запрос выполняй без повторного интервью; уточняй только недостающие решения. Отвечай на языке пользователя.
- Сначала прочитай [порядок работы](WORKFLOW.md); при расхождении его upstream-примеров с правилами этого раздела следуй этому разделу; дополнительные references загружай по выбранной ветке. Пути `scripts/`, `assets/`, `references/` относятся к каталогу этого навыка; выходные файлы — к рабочему проекту, не к установленному навыку.
- Используй доступные инструменты файлов, shell и вопросов Codex. Bash-примеры адаптируй к текущей ОС; найди Python, не предполагай наличие `python3`, `grep`, `unzip` или `/tmp`. Перед запуском помощника проверь его параметры и место записи.
- Предоставленный локальный TWX, код, BPMN или лог имеет приоритет над подключением к серверу. Для офлайн-работы учётные данные не нужны. Проверяй имена ZIP-записей перед распаковкой; работай в отдельном каталоге, не поверх исходника.
- Перед серверным вызовом прочитай [правила подключения](references/CREDENTIAL_HANDLING.md). Выбери подтверждённые версию BAW, адрес и context root. Справочники содержат сведения upstream, в том числе API 26.x; их наличие не гарантирует поддержку в IBM BPM 8.x или другой версии.
- Имена MCP-операций в workflow — описания возможностей, не гарантированно подключённые инструменты. Найди реальные инструменты и проверь их схемы. Если их нет, используй документированный REST только при доступе и подтверждённом контракте. Ошибку доступа сообщай, не маскируй.
- Для изменения сервера проверь объект, окружение, эффект и разрешённый пользователем объём. Не повторяй уже полученное согласование. Запрос анализа или генерации файлов не разрешает импорт, deploy, запуск тестового процесса, завершение задачи или удаление snapshot. После ошибки записи сначала проверь состояние, затем решай вопрос повтора.
- Подготовленный файл, локальная проверка и успешное выполнение на стенде — разные результаты. Сообщи выполненные проверки и ограничения. Этот набор не предоставляет универсальный API прямого сохранения скриптов и моделей в Process Designer.

## Особенности задачи

При переданном ID сначала проверь его существование и приложение чтением. Без ID выполни поиск. Не считай stuck синонимом suspended без проверки состояния. Retry, terminate и другие изменения требуют конкретного поручения.
