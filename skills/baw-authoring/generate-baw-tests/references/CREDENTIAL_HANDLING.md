# Подключение к BAW из Codex

Для локального анализа не подключайся к серверу. Для сетевого запроса используй настроенный connector/MCP с нужной операцией либо HTTP-клиент в отдельном процессе.

## Учётные данные

Сначала используй переменные окружения `BAW_BASE_URL`, `BAW_USERNAME`, `BAW_PASSWORD` или настроенный токен/секрет из окружения пользователя. Допустим явно выбранный локальный `.env`: читай его внутри процесса HTTP-клиента как данные, без `source`, `eval` и выполнения shell-подстановок. Значения не должны возвращаться в вывод инструмента или контекст модели.

Не печатай `.env`, пароль, Authorization, cookies, токены или ответ login целиком. Не подставляй реальные секреты в текст команды и аргументы CLI. В отчёте показывай только имена отсутствующих переменных и HTTP-статус. Если доступа нет, попроси настроить локальные секреты; не проси прислать пароль в чат. Учитывай настройки доступа среды, не обходи запрет чтения.

## HTTP и аутентификация

Адрес, порт, context root и способ аутентификации определяются по целевому окружению. Проверяй схему API именно его версии. Примеры URL в workflow не разрешают перебор других хостов/портов. Не считай пустой ответ списка серверов доказательством доступного playback runtime.

Для окружения с поддержкой Basic обычно требуется POST `<base>/ops/system/login`, затем cookie-сессия и `BPMCSRFToken`; точный контракт и допустимость Basic проверь по документации окружения. Для CP4BA или SSO используй настроенный механизм Zen/OIDC/API key: не переноси токен между разными origin и не подменяй аутентификацию по одному коду 401. REST-примеры в workflow и справочниках показывают форму запросов, а не готовые команды с секретами.

В Python используй `ssl.create_default_context()` и CookieJar в памяти; секреты загружай через `os.environ` или локальный конфигурационный файл внутри процесса. Для частного CA укажи доверенный CA bundle (например через `SSL_CERT_FILE`). TLS-проверка включена по умолчанию; при ошибке сертификата настрой доверенный CA, а не отключай проверку. Установи тайм-аут запроса. Проверяй origin перед переходом по redirect или queue URL и отправкой credentials.

На ошибке аутентификации останови зависимые вызовы и сообщи причину без секретов. Не повторяй изменение сервера вслепую после тайм-аута. Сохраняй служебные ответы только в локальные файлы с ограниченным доступом, если это нужно задаче; никогда в публичный репозиторий.
