# Выбрать задачу проекта

Прочитайте [workflow](references/workflow.md): он определяет поиск реестра,
документы, статусы и переход к реализации. Соглашения целевого проекта
имеют приоритет над значениями по умолчанию.

1. Найдите рабочий проект и реестр по workflow; если реестра нет, создайте его
   по правилам workflow. Прочитайте весь реестр.
   Покажите незавершённые задачи: ID, название, статус, ссылки на ТЗ/план,
   следующий шаг или блокер. Для завершённых и отменённых достаточно количества,
   если не запрошены детали. Неизвестные статусы и потерянные ссылки покажите.
2. Если запрошен только список, завершите после списка. Если реестр пуст,
   перейдите к разделу «Добавить первую задачу». Иначе предложите выбрать
   задачу или «Пока ничего». Используйте доступную форму вопросов с вариантами,
   например request_user_input_async; без неё — текстовый вопрос. Большой список
   разбейте на страницы до шести задач с навигацией и доступным полным списком.
   Навигация, предвыбранный вариант и молчание не считаются выбором.
3. Дождитесь выбора; неоднозначный свободный ответ уточните. Если задача уже
   явно указана, не спрашивайте её повторно. Выбор задачи определяет контекст,
   но сам по себе не разрешает разработку или изменение документов.
   «Пока ничего» оставляет задачи и статусы без изменений; созданный при запуске
   пустой реестр сохраняется.
4. Прочитайте запись TODO, существующие ТЗ (ФТ, требования, спецификацию),
   план и контекст продолжения. Сохраняйте названия и структуру документов:
   ТЗ и ФТ не требуют отдельных дублирующих файлов.
   Перейдите к разделу «Интерактивно выбрать действие» ниже. После выбора
   выполняйте действие, а не завершайте обещанием или повторным меню.
5. По результату дайте ID, действие, ссылки на документы, выполненные проверки
   и следующий шаг. Завершение одной задачи не запускает следующую.

Если реестр содержит только завершённые или отменённые задачи, сообщите
об отсутствии незавершённых задач без пустого меню выбора.
Для созданного реестра сообщите путь и отсутствие задач.
При явном поручении сформировать ТЗ новой задачи используйте её описание и переходите к выбору grill ниже. Если описания нет, запросите его; не выдумывайте задачу.

## Добавить первую задачу

При пустом TODO (нет ни одной записи) сразу задайте интерактивный вопрос:
«Реестр <путь к TODO> пуст. Добавить новую задачу?» Варианты:
«Добавить новую задачу» и «Пока ничего». Используйте request_user_input_async
или другую доступную форму вопросов; текстовый вопрос — только если формы нет.
Это относится и к только что созданному реестру. Явный запрос только списка
завершается без вопроса; уже порученное добавление задачи не требует повторного выбора.

Дождитесь явного ответа. При «Пока ничего» завершите, сохранив пустой реестр.
Предвыбранный вариант, молчание и истечение времени не разрешают добавление.
После выбора «Добавить новую задачу» запросите описание через свободное поле
формы: «Что нужно сделать и какой результат вы хотите получить?» Если описание
уже дано, используйте его. Неоднозначный ответ уточните до создания записи.

Получив описание, назначьте свободный ID по workflow и добавьте одну запись
со статусом draft (или местным эквивалентом), без ссылок на несуществующие
документы. Следующий шаг — выбрать действие и уточнить требования.
Затем перейдите к разделу «Интерактивно выбрать действие» с этим ID и описанием.
Добавление записи само по себе не запускает интервью или разработку.

## Интерактивно выбрать действие

Если пользователь явно задал действие, используйте его без повторного вопроса.
«Начни/продолжи разработку TASK-001» выбирает разработку; «сформируй ТЗ
через grill-me» выбирает этот навык. «Сформируй ТЗ» без имени навыка требует
выбора одного из двух grill. «Продолжи TASK-001» без ясного контекста действия
требует меню; уже согласованное действие текущей работы не спрашивайте заново.

Для выбранной задачи задайте самодостаточный вопрос:
«<ID> — <название>. ТЗ: <путь или отсутствует>. Статус: <статус>.
Что делаем дальше?» Предложите варианты:

- «ТЗ через grill-me» — уточнить требования, сценарии и критерии приёмки.
- «ТЗ через grill-with-docs» — также проработать терминологию, ADR и глоссарий.
- «Разработка по готовому ТЗ» — проверить имеющиеся требования и начать
  или продолжить реализацию.

Когда запрос ограничен подготовкой ТЗ, предложите только два grill-варианта.
Укажите рекомендацию с причиной; сохранённый навык используйте как рекомендацию,
а не как ответ пользователя. Разрешите отказаться или отложить работу.

Используйте доступный инструмент вопросов (например request_user_input_async)
с вариантами, иначе задайте вопрос текстом. Дождитесь явного ответа.
Предвыбранная рекомендация, молчание и истечение времени не являются выбором.
Неоднозначный ответ уточните. При отказе завершите без изменений выбранной задачи.

## Сформировать или уточнить ТЗ

1. Найдите выбранный установленный grill-навык и его зависимости, прочитайте
   инструкции. При отсутствии сообщите точное имя и источник установки,
   остановите зависимое интервью; не подменяйте его другим навыком автоматически.
   Соблюдайте режим вызова установленной версии.
2. Передайте ID, исходное описание, документы, принятые решения и открытые вопросы,
   а также правила сохранения из workflow. Проведите интервью выбранным навыком.
   Запишите выбранный навык в контекст продолжения. Если он изменился,
   сохраните историю решений и причину смены.
3. Сохраняйте ТЗ, план и запись TODO по мере появления результатов.
   Для новой задачи назначьте свободный ID и создайте одну запись; для существующей
   обновляйте её документы. ТЗ фиксирует цель, пользователей, сценарии, границы,
   ограничения, согласованные решения, критерии приёмки и открытые вопросы.
   План фиксирует этапы, зависимости и проверки. Соблюдайте формат проекта.
4. Неизвестное оставьте открытым; запросите подтверждение требований и критериев.
   Черновик получает draft, согласованная задача — ready или местные эквиваленты.
   Для уже начатой задачи сохраняйте фактический прогресс: корректировка ТЗ
   не обнуляет сделанную работу; блокирующее изменение отражайте по workflow.
5. Сообщите ID, ссылки на ТЗ/план/TODO, согласованные решения и оставшиеся вопросы.
   Подготовка ТЗ не запускает реализацию автоматически. Если пользователь ранее
   явно поручил и подготовку, и последующую разработку, после согласования
   переходите к проверкам следующего раздела без повторного разрешения.

## Разрабатывать по существующему ТЗ

1. Прочитайте ТЗ и план полностью, сверьте с кодом и текущим прогрессом.
   Проверьте наличие согласованных требований, критериев приёмки и отсутствие
   блокирующих вопросов. Статус ready сам по себе не доказывает готовность.
   Для in_progress продолжите первый незавершённый этап.
2. Если ТЗ отсутствует, недоступно, противоречиво или не согласовано, сообщите
   конкретный пробел. Предложите указать существующий документ либо выбрать
   один из двух grill-навыков для его подготовки/уточнения. Дождитесь решения;
   не начинайте зависимую разработку и не меняйте режим молча.
3. При достаточных требованиях выполняйте раздел «Начать или продолжить выбранную
   задачу» workflow: местные правила веток, реализация, проверки, обновление
   прогресса. Действуйте, а не завершайте одним планом. Grill-зависимости
   не нужны для реализации, когда уточнение требований не требуется.
4. Перед done сопоставьте каждый критерий приёмки с результатом и проверкой.
   Укажите, что сделано, что проверено и что осталось; публикация и деплой
   требуют соответствующего поручения по правилам проекта.

## Внешние зависимости

Grill-навыки и domain-modeling не входят в этот набор. Установите из
[каталога mattpocock/skills](https://github.com/mattpocock/skills)
grill-me, grill-with-docs, grilling и domain-modeling по инструкции каталога
для вашего агента, включая зависимости выбранной версии.

Перед интервью найдите установленный навык через доступный каталог навыков
или механизм плагинов и прочитайте его инструкции. Не предполагайте, что
он находится в соседней папке. Соблюдайте его режим вызова; если требуется
явный запуск пользователем, дайте команду с контекстом задачи.
Если зависимость отсутствует, сообщите её имя и ссылку на установку,
приостановите только зависимое интервью. Просмотр TODO остаётся доступным.
Не устанавливайте зависимости автоматически без поручения пользователя.

Сохранение требований, плана и TODO обеспечивает project-todo по своему
workflow: внешние навыки не обязаны знать этот формат. Передайте им контекст
задачи и правила сохранения; после интервью проверьте документы и реестр.
